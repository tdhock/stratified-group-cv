\begin{abstract}
  Cross-validation is used throughout machine learning for model training and evaluation.
  In classification data sets, stratification is used to ensure that splits preserve class proportions.
  In structured data (image segmentation, medical visits, etc.), grouping is used to prevent data leakage (data from the same group should not appear in both train and test sets).
  Fold assignment is trivial with either stratification or grouping, but it is NP-hard with both stratification and grouping.
  Scikit-learn implements a heuristic that obtains reasonable fold assignments in this case, but its time and memory complexity can be prohibitive for large data.
  We propose a new heuristic algorithm with asymptotically less time and memory usage, that can be used on large data sets.
  In an empirical analysis of four real data sets, the proposed algorithm provides comparable fold assignments, and is asymptotically about ten times faster than the previous algorithm.
\end{abstract}

Many types of modern artificially intelligent systems are powered by machine learning: image classification, medical diagnosis/prognosis, automatic translation, etc.
$K$-fold cross-validation \citep{Arl_Cel:2010:surveyCV,raschka2020modelevaluationmodelselection} is a fundamental data-splitting technique that is used for both training (tuning hyper-parameters of a learning algorithm) and evaluation (comparing prediction accuracy of different learning algorithms).
In a data set of $N$ observations (rows of tabular data), $K$-fold cross-validation involves assigning a fold ID (integer between 1 and $K$) to each of the $N$ rows.
For each fold ID from 1 to $K$, the corresponding rows form a test set, and the other rows form a train set (for the case of evaluation).
Learning algorithms are fit to each train set, then prediction error rates are computed on the corresponding test set.
The resulting $K$ measurements of prediction error on the test sets are used to estimate how the learning algorithm would perform on new data from the same distribution.


\subsection{Issues with unstructured cross-validation in structured data}

This paper proposes a new algorithm for cross-validation in machine learning data sets with two kinds of structure: groups and strata.
Groups are rows that should stay together when splitting, to avoid data leakage, which can cause over-optimistic estimates of prediction error rates  \citep{kaufman2012leakage,kapoor2023leakage}.
Examples of groups include medical records for the same patient (in diagnostic/prognostic prediction problems), and pixels labeled from the same polygon (in image segmentation problems).
Strata are classes of rows for which the relative proportions should be preserved when splitting.
Examples of strata include the output label in classification problems, such as medical diagnosis or image segmentation \citep{russell2008labelme, asif2025advancements}.
To understand why our proposed algorithm is useful, we first discuss the issues that arise when unstructured cross-validation is used in structured data.

\subsubsection{
  % Cross-validation with neither
  Neither stratification nor groups}

Because the goal of data-splitting is to estimate prediction error in the same distributional setting as the original data set, it is important for the splitting procedure to generate train/test sets which are representative of the original data.
In an unstructured data set, we would at least like to ensure that each test set has the same number of rows.
For example, consider the AZtrees data \citep{Hocking2026soak}, which represent an image segmentation problem.
There are $N=5956$ rows, each representing a pixel in an image that has been labeled as containing a tree (positive class) or not (background negative class), so in $K=3$ fold cross-validation, we expect each fold to have approximately $N/K=1985.33$ rows.
Standard unstructured cross-validation repeats the sequence of fold values ($1, \dots, K, 1, \dots, K, \dots$), to obtain an $N$-vector which is then randomly shuffled.
This guarantees approximately the same number of rows in each fold (at most one row difference, when $N/K$ is not an integer).
For the AZtrees example, this results in 1985--1986 rows per fold (Table~\ref{tab:counts} Case A Total).

\subsubsection{
  % Cross-validation with
  Stratification but no groups}

However, the random shuffling in unstructured cross-validation can cause substantial variation between class frequencies, which is undesirable.
For the AZtrees example, one random shuffle gave 1749--1772 Negative rows and 213--237 Positive rows (Table~\ref{tab:counts} Case A Negative and Positive).
To get class frequencies that are approximately equal across folds (at most one row different), cross-validation can be stratified using the class.
For a stratum/class with $c$ rows, we repeat the fold values ($1, \dots, K, 1, \dots, K, \dots$), to obtain a $c$-vector, then assign the shuffled fold values to the rows in that class/stratum.
For the AZtrees example, stratification results in 1760--1761 negative rows per fold, and 224--225 positive rows per fold.
(Table~\ref{tab:counts} Case B Negative and Positive).

\subsubsection{%Cross-validation with
  Groups but no stratification}

In a structured data set with a grouping variable, the data-splitting technique should work on groups instead of rows, to avoid data leakage \citep{kaufman2012leakage,kapoor2023leakage}.
For example, the AZtrees data were created by drawing polygons on a map in Quantum GIS software \citep{QGIS_software}.
Each polygon represents an area of the map labeled as positive or negative, and all pixels in the polygon are assigned the corresponding class label.
We would like to avoid generating a split with some pixels of a polygon assigned to the train set, and other pixels from that polygon assigned to the test set (data leakage), which would result in over-optimistic estimates of test error rates.
In the AZtrees data, cross-validation without grouping by polygon results in data leakage: some groups are randomly assigned to multiple folds (Table~\ref{tab:counts} Cases A and B, 1--104 groups in multiple folds).

To modify cross-validation for a data set with $G$ groups, we repeat the fold values ($1, \dots, K, 1, \dots, K, \dots$), to obtain a $G$-vector, which is randomly shuffled to assign each group to a fold.
Grouped cross-validation always results in approximately the same number of groups in each fold (max difference of 1 group if $G/K$ is not an integer).
The AZtrees data has $G=189$ groups, so grouped cross-validation with $K=3$ folds results in $G/K=63$ groups per fold (Table~\ref{tab:counts} Case C Total).

However, simple grouped cross-validation only ensures approximately equal numbers of groups (not rows) across folds, so each fold can have very different row counts.
In the AZtrees example, one random shuffle gave 1253--2577 rows per fold (Table~\ref{tab:counts} Case C Total).
Furthermore, simple grouped cross-validation does not perform stratification, so each fold can have very different class frequencies.
In the AZtrees example, one random shuffle gave 167--320 positive rows per fold, and 1066--2410 negative rows per fold (Table~\ref{tab:counts} Case C Negative and Positive).

\subsection{Proposed algorithm for cross-validation with stratification and groups}

Are there efficient algorithms that can handle stratification and grouping?
Yes, but any efficient algorithm must be heuristic, because this assignment problem is NP-hard when each group has an arbitrary number of rows per stratum.
An ideal algorithm would result in the same class frequencies in each fold, and no data leakage (Table~\ref{tab:counts} Case E).

This paper proposes a new heuristic algorithm which performs greedy minimization of the difference between expected and ideal row counts across folds, while respecting the group constraint to avoid data leakage.
In the AZtrees data, one random run of the proposed heuristic without stratification gave 1985--1986 rows per fold, 1723--1803 negative labels per fold, 183--262 positive labels per fold, and no data leakage (Table~\ref{tab:counts} Case D).
With stratification, the proposed heuristic gave an ideal result: 1985--1986 rows per fold, 1760--1761 negative labels per fold, 224--225 positive labels per fold, and no data leakage (Table~\ref{tab:counts} Case E).

Our proposed heuristic is inspired by previous work by a Kaggle competitor, who proposed a different heuristic algorithm, based on minimizing the variance between row counts in each fold \citep{Wasikowski2019}.
We refer to this previous algorithm as the Wasikowski heuristic, which is used in the StratifiedGroupKFold class, available in scikit-learn since version 1.0 \citep{pr18649,whatsnew}.
However, close inspection of the Wasikowski heuristic reveals that it is relatively inefficient, $O(K^2 SG)$ time and $O(SG)$ memory for $K$ folds, $G$ groups, and $S$ strata (Table~\ref{tab:complexity}).
The quadratic time complexity can be prohibitive for a large number of folds $K$, and the memory complexity can be prohibitive if both $S$ and $G$ are large.
This paper proposes new heuristic algorithms with reduced asymptotic time and memory complexity (Table~\ref{tab:complexity}).


\subsection{Contributions}

This paper presents five new research contributions related to cross-validation with groups and strata.
After reviewing related research (Section~\ref{sec:related}), we present a new abstract characterization of the previous Wasikowski algorithm, which allows understanding and improving three sub-routines (Contribution~1, Section~\ref{sec:pseudo-code}).
Next, we propose a new online counting algorithm, with asymptotically less memory usage (Contribution~2, Section~\ref{sec:online}), which permits new applications to data sets with large numbers of strata and groups.
We propose a new RSS minimization algorithm which is asymptotically faster than the previous Wasikowski algorithm (Contribution~3, Section~\ref{sec:RSS-algo}).
To demonstrate the advantages of our new algorithm, we propose synthetic data sets to use as test cases (Contribution~4, Section~\ref{sec:synthetic-tests}).
Finally, we present systematic empirical comparisons with 5 baselines, in terms of fold assignment accuracy and computation time in four real data sets (Contribution~5, Section~\ref{sec:results}).

\section{Related Work}
\label{sec:related}

A typical application of stratification is in classification problems, where the stratum variable is defined as the label/output variable to predict.
Other examples of stratification variables are domain/subset, when evaluating domain adaptation algorithms, and when estimating similarity of data subsets for learning purposes \citep{Hocking2026soak}.

Assigning groups of data to cross-validation folds is similar to the bin packing problem, which is NP-hard, but with fast heursitic algorithms that have reasonable approximation error bounds \citep{Johnson2016}.
Two classic algorithms are ``first fit decreasing'' and ``best fit decreasing,'' both of which sort the list of objects by size, and have asymptotic worst case ratios of 11/9 (amount of more bins used than necessary).
Whereas bin packing has a variable number of bins used for $N$ items, cross-validation has a fixed number of $K$ bins, so is a different NP-hard problem: multiway number partitioning, which has been called the ``easiest hard problem'' \citep{hayes2002computing}.
%With more than one stratum, this 
Simple heuristics for this problem are similar to bin packing: sort by size and then use greedy assignment to the emptiest bin.
Other heuristics for this problem include genetic algorithms and local search \citet{Pop2013}, which are too complex for the cross-validation fold assignment problem.

We provide empirical comparisons with previous algorithms and software for cross-validation fold assignment in scikit-learn \citep{sklearn2011}, \texttt{bioLeak} \citep{bioLeak2026}, \texttt{rsample} \citep{rsample2026}, and \texttt{origami} \citep{Coyle2018,origami2026}.

\section{Algorithms}

Assume we have a data set with $N$ rows in $S$ strata and $G$ groups.
We want to perform $K$-fold cross-validation, such that data in each group are assigned the same fold ID (no data leakage), and the strata proportions are approximately equal across folds.

\subsection{Pseudo-code for greedy fold assignment}
\label{sec:pseudo-code}
The previous Wasikowski algorithm, and our proposed algorithms, are all greedy heuristics which we summarize using the pseudo-code:
\begin{verbatim}
def assign_folds(strata, groups, N_folds):
  count_matrix = zeros(N_strata, N_folds)
  folds = {}
  for group in Sort(groups):
    best_fold = get_best_fold(group)
    folds[group] = best_fold
    count_matrix[,best_fold] += count(group)
  return folds
\end{verbatim}
This is a novel abstract characterization of the previous algorithm (Contribution~1), which facilitates understanding and improving its computational complexity.
The algorithm inputs $N$-vectors \texttt{strata} ($S$ unique values) and \texttt{groups} ($G$ unique values), as well as \texttt{N\_folds} (integer, $K$).
The greedy algorithm requires storing the current number of strata assigned to each fold in \texttt{count\_matrix}, which starts with zeros.
The $O(N\log N)$ time \texttt{Sort()} sub-routine is used to determine the order groups will be considered by the greedy algorithm, and then each group is assigned to a fold in the for loop.
For each group, the \texttt{get\_best\_fold()} sub-routine determines the fold assignment, which is stored for output, and used to update \texttt{count\_matrix}.

\subsection{Previous Wasikowski algorithm}

The previous Wasikowski algorithm uses the following choices for the sub-routines in the pseudo-code.
The \texttt{Sort()} sub-routine uses the variance of the strata counts (max variance assigned first), which has some drawbacks that are discussed in Section~\ref{sec:synthetic-tests}.
The $O(K^2 S)$ time \texttt{get\_best\_fold()} sub-routine loops over possible folds, adding the current group’s strata counts to current fold’s column of \texttt{count\_matrix}, which is then summarized by computing standard deviation (SD) over folds for each stratum, and finally mean of the SD values over strata.
The \texttt{count(group)} sub-routine involves computing a matrix of counts for each stratum and group, which takes $O(SG)$ memory.
This algorithm is implemented in scikit-learn \citep{sklearn2011}, and has overall $O(N\log N+K^2SG)$ time, $O(N+KS+SG)$ memory complexity (Wasikowski algorithm in Table~\ref{tab:complexity}).

\subsection{Proposed online counting algorithm for reduced memory complexity}
\label{sec:online}
The previous algorithm’s $O(SG)$ memory complexity can be prohibitive if there are a large number of strata and groups.
We propose to sort all data rows by group, so the for loop over groups becomes a for loop over data rows, and the \texttt{count(group)} sub-routine computes a vector of strata counts for the current group (no need for a matrix of counts for every group and stratum).
This proposed online counting algorithm can be used with the previous heuristic (Wasikowski-L in Table~\ref{tab:complexity}), and with our proposed squared error minimization heuristic (RSS in Table~\ref{tab:complexity}).
Both are the first such algorithms with no $O(SG)$ term in memory complexity (Contribution~2), which permits new applications of these algorithms to data with a large number of strata and groups.
\subsection{Proposed RSS minimization for reduced time complexity}
\label{sec:RSS-algo}
The main new idea of the proposed algorithm is to minimize the Residual Sum of Squares (RSS) between the ideal and actual row counts per fold/stratum (Contribution~3).
\subsubsection{Proposed Sort() sub-routine}
\label{sec:proposed-sort}
For each row $i\in\{1,\dots,N\}$, we have a stratum $s_i\in\{1,\dots,S\}$.
The algorithm begins by counting the number of rows in each stratum, then dividing by the number of folds, to obtain the ideal number of rows which could appear in each fold.
For each stratum $\sigma\in\{1,\dots,S\}$, the ideal number of rows is
\begin{equation}
n^*_\sigma = \sum_{i\in\{1,\dots,N\}}
I[s_i = \sigma]/K,
\end{equation}
where $I[\cdot]$ is the indicator function (1 if argument is true, 0 otherwise).
Table~\ref{tab:results} (row ``ideal per fold'') shows $n^*_\sigma$ values for $K=4$ fold cross-validation in four real data sets.

The proposed Sort() sub-routine sorts groups by RSS (increasing).
To compute the RSS for each group, we first compute $c_1,\dots,c_S $, the counts of rows in each stratum for the current group, \texttt{count(group)} in the pseudo-code.
Then we define the RSS for that group as the squared error between ideal and group counts, summed over strata,
%\begin{equation}
$
\sum_{\sigma\in\{1,\dots,S\}}
(c_{\sigma} - n^*_\sigma)^2.
$
%\end{equation}
If there are two groups with the same RSS value, we break ties by sorting using the number of rows in that group (decreasing),
$\text{Nrow}=
\sum_{\sigma\in\{1,\dots,S\}}
c_{\sigma},
$
and do a third level of tie-breaking by sorting by the weighted sum (decreasing),
$\text{Wsum}=
\sum_{\sigma\in\{1,\dots,S\}}
c_{\sigma}n^*_\sigma.
$
These sorting rules can be justified as analogous to the ``pack larger bins first'' heuristic \citep{Johnson2016}.
In Section~\ref{sec:synthetic-tests}, we propose illustrative synthetic data to justify these sorting rules.

\subsubsection{Proposed greedy fold assignment}

Our proposed \texttt{get\_best\_fold()} sub-routine is defined as follows.
For each stratum $\sigma$ and fold $\phi\in\{1,\dots,K\}$, let $\hat n_{\sigma,\phi}$ be the number of data with that stratum assigned to that fold (\texttt{count\_matrix} in the pseudo-code).
We propose to find a fold assignment which minimizes the residual sum of squares,
\begin{equation}
\text{RSS}=
\sum_{\sigma\in\{1,\dots,S\}}
\sum_{\phi\in\{1,\dots,K\}}
(\hat n_{\sigma,\phi} - n^*_\sigma)^2.
\label{eq:RSS}
\end{equation}

The algorithm starts with all $\hat n_{\sigma,\phi}=0$ and then assigns a fold to one group at a time.
We propose assigning the group to the fold that minimizes the RSS after assignment,
\begin{equation}
\min_{k\in\{1,\dots,K\}}
\sum_{\sigma\in\{1,\dots,S\}}
\sum_{\phi\in\{1,\dots,K\}}
\big(
(\hat n_{\sigma,\phi}+c_\sigma I[\phi=k]) - n^*_\sigma\big)^2.
\end{equation}
Expanding the square and simplifying yields
\begin{eqnarray}
  \min_{k\in\{1,\dots,K\}}
  &&
     \sum_{\sigma\in\{1,\dots,S\}}
     \sum_{\phi\in\{1,\dots,K\}}
     \hat n^2_{\sigma,\phi}
     - 2 \hat n_{\sigma,\phi} n^*_\sigma+ {n^*_\sigma}^2
     \nonumber\\
  &&
+ I[\phi=k] c_\sigma ( 2 \hat n_{\sigma,\phi} + c_\sigma - 2n^*_\sigma ).
\end{eqnarray}
The first three terms above are the current RSS~(\ref{eq:RSS}), which does not depend on $k$, so it is a constant that we can remove from the min.
Furthermore, the indicator function cancels the sum over folds $\phi$:
\begin{equation}
\text{RSS} + \min_{k\in\{1,\dots,K\}}
\sum_{\sigma\in\{1,\dots,S\}}
c_\sigma ( 2 \hat n_{\sigma,k} + c_\sigma - 2n^*_\sigma ),
\end{equation}
% Simplifying yields
% \begin{equation}
% \text{RSS} + \min_{k\in\{1,\dots,K\}}
% \sum_{\sigma\in\{1,\dots,S\}}
% c_\sigma\big(c_\sigma+2(\hat n_{\sigma,k}-n^*_\sigma)\big),
% \end{equation}
which can be solved in $O(KS)$ time.
Taking the argmin, we remove terms that do not depend on $k$:
\begin{equation}
  \label{eq:k*}
k^* = 
\argmin_{k\in\{1,\dots,K\}}
\sum_{\sigma\in\{1,\dots,S\}}
c_\sigma \hat n_{\sigma,k}.
\end{equation}
We propose using~(\ref{eq:k*}) for the \texttt{get\_best\_fold()} sub-routine in the pseudo-code, with tie-breaking by taking the fold which results in minimal counts larger than ideal.
The proposed RSS minimization procedure~(\ref{eq:k*}) has a sum over $S$ terms inside a min over $K$ terms, yielding a  $O(SK)$ time  \texttt{get\_best\_fold()} sub-routine.
Comparing to the previous Wasikowski algorthm, the proposed RSS minimization is asymptotically faster (linear rather than quadratic in the number of folds $K$).
The overall complexity of the proposed RSS minimization algorithm is therefore $O(N\log N+KSG)$ time and $O(N+KS)$ memory (Table~\ref{tab:complexity}).

\subsection{Test case to justify sorting by RSS}

% This equation assigns the fold ID which results in min RSS.
% If there is more than one fold with the same RSS value, then we tie-break by minimizing the amount past the ideal.
% For example, if ideal is 100, then 99 should be preferred over 101 (even though both have same RSS).

% Each group is represented by a vector of counts, one element per stratum.
% For example with 3 strata, two count vectors are [ 3, 3, 2 ] and [ 0, 1, 0 ].
% Previous sort method uses SD, so [ 3, 3, 2 ] is tied with [ 0, 1, 0 ].
% However a common heuristic for bin packing is to pack larger items first.
% The proposed sort uses RSS of group count vector: sum of squared differences between actual and ideal counts.
% The ideal counts are always large, so [ 3, 3, 2 ] has smaller RSS, and our proposed algorithm therefore inserts it before [ 0, 1, 0 ], as desired.

% [ 1, 0 ] has variance 0.5 so is inserted before [ 1, 1 ] and [ 10, 10 ], both variance 0.
% But we want to insert [ 10, 10 ] first (pack larger items first).
% Our algo achieves this desired insertion order: [ 10, 10 ] then [ 1, 1 ] then [ 1, 0 ].
% The proposed algo results in better fold assignments for these simple examples.

We propose the following synthetic test case to show the advantage of the proposed algorithm (sort groups by RSS increasing), relative to the previous Wasikowski algorithm (sort by variance decreasing).
Consider the following data set with $S=2$ strata, $G=5$ groups, $N=12$ data, and $K=3$ fold cross-validation (Table~\ref{tab:rss-var}).
We use the notation $[c_1,c_2]$ for $c_1$ rows in stratum 1, and $c_2$ rows in stratum 2.
Consistent with the ``pack larger bins first'' heuristic, the proposed algorithm sorts the five groups in the order [1,3], [1,2], [0,2], [1,1], [0,1].
The previous Wasikowski algorithm sorts in an order that is not consistent with the number of rows: [1,2] and [0,1] both have variance 0.5, so are assigned folds before [1,1] (zero variance).
For these data, the proposed RSS minimization always obtains ideal counts per fold, [1,3] (Table~\ref{tab:rss-var}, left).
In contrast, the previous method can result in sub-optimal counts: [1,4],[1,3],[1,2] (Table~\ref{tab:rss-var}, right).

\subsection{Test case to justify tie-breaking}

We propose the following synthetic data set where the tie-breaking rules (Section~\ref{sec:proposed-sort}) are necessary for optimal fold assignment.
It involves $N=22$ data with $G=6$ groups, $S=2$ strata, and $K=2$ folds (Table~\ref{tab:ties}).
The groups are [1,1], [3,0],  [5,3], and three groups with the counts [1,2].
The total is [12,10], so the ideal is $n^*=[6,5]$ per fold.
The groups [3,0] and [1,2] are tied for the first two sorting criteria: RSS=34 and Nrow=3.
To third level of tie-breaking should prefer the group [3,0] which has more rows than [1,2] in the larger first stratum.
Our proposed third criterion is the weighted sum,
$\text{Wsum}=
\sum_{\sigma\in\{1,\dots,S\}}
c_{\sigma}n^*_\sigma,
$
which is 18 for [3,0] and 16 for [1,2].
Using this tie-breaking rule in these data, the greedy heuristic always obtains ideal counts of [6,5] for both folds (Table~\ref{tab:ties}, right).
Omitting this rule can result in sub-optimal counts: one fold with [6,4] and the other with [6,6] (Table~\ref{tab:ties}, left).

\section{Real data results}
\label{sec:results}
We present systematic comparisons with previous algorithms and software (Contribution~5).
All results were computed on a 2025 laptop (Intel Core Ultra 5 125U CPU).

\subsection{Data sets}

We chose four data sets in order to represent a variety of different application areas of machine learning, over several orders of magnitude of size, from $N=444$ to $N=248,485$ rows.

We considered two medical data sets in which groups are patients and rows are medical visits, so grouped cross-validation is important to ensure accurate estimation of prediction error on new patients.
The \textbf{respiratory} data have $N=444$ rows and $G=111$ groups for respiratory illness prediction, from the geepack package in R \citep{Halekoh2006}.
The \textbf{Laribi2024} data from Zenodo \citep{Laribi2024} have $N=248,485$ rows and $G=123,646$ groups for one year mortality prediction at emergency room admission \citep{Laribi2025}.
There are $S=2$ strata/labels: affected or not by illness/death.

In image segmentation, labels are often created using polygons, and each pixel in the polygon becomes a data row with the corresponding label.
Using polygons as groups in cross-validation ensures accurate estimation of prediction error on new polygons.
The \textbf{AZtrees} data have $N=5956$ rows and $G=189$ groups for predicting presence versus absence of trees in satellite images of Arizona \citep{Hocking2026soak} ($S=2$ strata).

The previous Wasikowski algorithm was originally motivated by a Kaggle data set about pet adoption \citep{Wasikowski2019}.
In the \textbf{PetAdoption} data, there are $N=14,993$ rows, each row is a pet, and pets are grouped by rescuer ($G=5595$ groups).
There are $S=5$ strata/labels: categories of adoption speed.

\subsection{Baseline algorithms}

We compared the proposed RSS algorithm to five others.
First, the random baseline is the trivial algorithm which assigns each group to a random fold (no leakage, but high error rate, case C in Figure~\ref{tab:counts}).
Second, we ran the previous Wasikowski algorithm, which has a Python/numpy implementation in scikit-learn \citep{sklearn2011}.
We re-implemented this algorithm in C++ for a more controlled comparison with our proposed C++ code for RSS minimization.
We also ran three packages in R \citep{R2026} with functions for computing fold assignment using stratification and groups: 
\texttt{bioLeak} version 0.3.8 \citep{bioLeak2026}, \texttt{rsample} version 1.3.2 \citep{rsample2026}, \texttt{origami} version 1.0.8 \citep{Coyle2018,origami2026}.

\subsection{Accuracy of fold assignment}

To compare fold assignment accuracy, we ran all six algorithms on all four data sets, using $K\in\{2,4,8\}$ folds, and ten random seeds which control final tie-breaking in the sort step.
We expected the proposed algorithm to create near ideal fold assignments, similar to the previous heuristic.
For $K=4$ folds and one random seed, Table~\ref{tab:results} shows the counts obtained using four methods (ideal, proposed RSS, previous Wasikowski, random baseline).
In agreement with our expectations, these results show that the proposed algorithm yields fold assignments with nearly ideal counts in all data sets, similar to the previous Wasikowski heuristic (both much better than random).
The only exception was in AZtrees data, for which any algorithm fails, due to one large group with 1478 rows (assigned to a single fold to avoid data leakage, resulting in counts much larger than ideal).

For each run, we also computed and plotted the root mean squared error between the ideal and actual counts per fold/stratum (Figure~\ref{fig:several_Tasks}).
In agreement with our expectations, we observed that proposed RSS and previous Wasikowski had comparably small error rates (sometimes one or the other slightly better, almost always much smaller error rates than random).
The origami and rsample R packages require one stratum per group, so only run in the AZtrees data, but gave error rates similar to random (with data leakage for origami).
The bioLeak package ran in all data, but almost always yielded error rates much larger than the proposed RSS and previous Wasikowski algorithms.
Overall, these results indicate that the proposed RSS algorithm provides state-of-the-art fold assignment accuracy for a variety of real data sets with groups and strata.

\subsection{Empirical timings}

We expected the greedy fold assignment step of our proposed RSS algorithm to be asymptotically faster than the previous Wasikowski algorithm.
We therefore ran empirical timings on the Laribi2024 data, varying number of folds $K$.
We fit asymptotic references to the empirical timings (Figure~\ref{fig:Laribi-refs}, left), which indicated $O(K^2)$ time for the previous Wasikowski algorithm, and $O(K)$ time for the proposed RSS algorithm (as expected).
We then varied number of rows $N$ (keeping $K=10$ folds constant), which gave a similar asymptotic slope on the log-log plot, but with the proposed RSS algorithm faster by a factor of about 10 (Figure~\ref{fig:Laribi-refs}, right).
Overall, these empirical timings suggest that the proposed RSS algorithm is much faster than the previous Wasikowski algorithm.

\section{Conclusions}

In structured data sets with groups and strata, cross-validation fold assignment is NP-hard.
We proposed a new greedy algorithm that has asymptotically less time and memory usage than the previous Wasikowski algorithm in scikit-learn.
Our empirical results on synthetic and real data showed that our proposed algorithm is at least as accurate, and much faster, than the previous Wasikowski algorithm.
Future work could consider 
other loss functions like a max difference \citep{Pop2013},
or adapting our algorithm for new applications such as imbalanced subset generation.
