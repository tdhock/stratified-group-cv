\begin{abstract}
  Cross-validation is used throughout machine learning for model training and evaluation.
  In classification data sets, stratification is used to ensure that splits preserve class proportions.
  In structured data (image segmentation, medical visits, etc.), grouping is used to prevent data leakage (data from the same group should not appear in both train and test sets).
  Fold assignment is trivial with either stratification or grouping, but it is NP-hard with both stratification and grouping.
  Scikit-learn implements a heuristic that obtains reasonable fold assignments in this case, but its time and memory complexity can be prohibitive for large data.
  We propose a new heuristic algorithm with asymptotically less time and memory usage, that can be used on large data sets.
  In an empirical analysis of four real data sets, the proposed algorithm provides comparable fold assignments, and is at least ten times faster than the previous algorithm.
\end{abstract}

Many types of modern artificially intelligent systems are powered by machine learning: image classification, medical diagnosis/prognosis, automatic translation, etc.
$K$-fold cross-validation is a fundamental data-splitting technique that is used for both training (tuning hyper-parameters of a learning algorithm) and evaluation (comparing prediction accuracy of different learning algorithms).
In a data set of $N$ observations (rows of tabular data), $K$-fold cross-validation involves assigning a fold ID (integer between 1 and $K$) to each of the $N$ rows.
For each fold ID from 1 to $K$, the corresponding rows form a test set, and the other rows form a train set (for the case of evaluation).
Learning algorithms are fit to each train set, then prediction error rates are computed on the corresponding test set.
The resulting $K$ measurements of prediction error on the test sets are used to estimate how the learning algorithm would perform on new data from the same distribution.

\subsection{Issues with unstructured cross-validation in structured data}

This paper proposes a new algorithm for cross-validation in machine learning data sets with two kinds of structure: groups and strata.
Groups are rows that should stay together when splitting, to avoid data leakage, which can cause over-optimistic estimates of prediction error rates (TODO citation).
Examples of groups include medical records for the same patient (in diagnostic/prognostic prediction problems), and pixels labeled from the same polygon (in image segmentation problems).
Strata are classes of rows for which the relative proportions should be preserved when splitting.
Examples of strata include the output label in classification problems, and the domain/subset variable in domain adapation evaluation (TODO citation).
To understand why our proposed algorithm is useful, we first discuss the issues that arise when unstructured cross-validation is used in structured data.

\subsubsection{Cross-validation with neither stratification nor groups}

Because the goal of data-splitting is to estimate prediction error in the same distributional setting as the original data set, it is important for the splitting procedure to generate train/test sets which are representative of the original data.
In an unstructured data set, we would at least like to ensure that each test set has the same number of rows.
For example, consider the AZtrees data \citep{Hocking2026soak}, which represent an image segmentation problem.
There are $N=5956$ rows, each representing a pixel in an image that has been labeled as containing a tree (positive class) or not (background negative class), so in $K=3$ fold cross-validation, we expect each fold to have approximately $N/K=1985.33$ rows.
Standard unstructured cross-validation repeats the sequence of fold values ($1, \dots, K, 1, \dots, K, \dots$), to obtain an $N$-vector which is then randomly shuffled.
This guarantees approximately the same number of rows in each fold (at most one row difference, when $N/K$ is not an integer).
For the AZtrees example, this results in 1985--1986 rows per fold (Table~\ref{tab:counts} Case A Total).

\subsubsection{Cross-validation with stratification but no groups}

However, the random shuffling in unstructured cross-validation can cause substantial variation between class frequencies, which is undesirable.
For the AZtrees example, one random shuffle gave 1749--1772 Negative rows and 213--237 Positive rows (Table~\ref{tab:counts} Case A Negative and Positive).
To get class frequencies that are approximately equal across folds (at most one row different), cross-validation can be stratified using the class.
For a stratum/class with $c$ rows, we repeat the fold values ($1, \dots, K, 1, \dots, K, \dots$), to obtain a $c$-vector, then assign the shuffled fold values to the rows in that class/stratum.
For the AZtrees example, stratification results in 1760--1761 negative rows per fold, and 224--225 positive rows per fold.
(Table~\ref{tab:counts} Case B Negative and Positive).

\subsubsection{Cross-validation with groups but no stratification}

In a structured data set with a grouping variable, the data-splitting technique should work on groups instead of rows, to avoid data leakage (TODO citation).
For example, the AZtrees data were created by drawing polygons on a map (TODO citation).
Each polygon represents an area of the map labeled as positive or negative, and all pixels in the polygon are assigned the corresponding class label.
We would like to avoid generating a split with some pixels of a polygon assigned to the train set, and other pixels from that polygon assigned to the test set (data leakage), which would result in over-optimistic estimates of test error rates.
In the AZtrees data, cross-validation without grouping by polygon results in data leakage: some groups are randomly assigned to multiple folds (Table~\ref{tab:counts} Cases A and B, 1--104 groups in multiple folds).

To modify cross-validation for a data set with $G$ groups, we repeat the fold values ($1, \dots, K, 1, \dots, K, \dots$), to obtain a $G$-vector, which is randomly shuffled to assign each group to a fold.
Grouped cross-validation always results in approximately the same number of groups in each fold (max difference of 1 group if $G/K$ is not an integer).
The AZtrees data has $G=189$ groups, so grouped cross-validation with $K=3$ folds results in $G/K=63$ groups per fold (Table~\ref{tab:counts} Case C Total).

However, simple grouped cross-validation only ensures approximately equal numbers of groups (not rows) across folds, so each fold can have very different row counts.
In the AZtrees example, one random shuffle gave 1253--2577 rows per fold (Table~\ref{tab:counts} Case C Total).
Furthermore, simple grouped cross-validation does not perform stratification, so each fold can have very different class frequencies.
In the AZtrees example, one random shuffle gave 167--320 positive rows per fold, and 1066--2410 negative rows per fold (Table~\ref{tab:counts} Case C Negative and Positive).

\subsection{Proposed algorithm for cross-validation with stratification and groups}

Are there efficient algorithms that can handle stratification and grouping?
Yes, but any efficient algorithm must be heuristic, because this assignment problem is NP-hard when each group has an arbitrary number of rows per stratum.
An ideal algorithm would result in the same class frequencies in each fold, and no data leakage (Table~\ref{tab:counts} Case E).

This paper proposes a new heuristic algorithm which performs greedy minimization of the difference between expected and ideal row counts across folds, while respecting the group constraint to avoid data leakage.
In the AZtrees data, one random run of the proposed heuristic without stratification gave 1985--1986 rows per fold, 1723--1803 negative labels per fold, 183--262 positive labels per fold, and no data leakage (Table~\ref{tab:counts} Case D).
With stratification, the proposed heuristic gave an ideal result: 1985--1986 rows per fold, 1760--1761 negative labels per fold, 224--225 positive labels per fold, and no data leakage (Table~\ref{tab:counts} Case E).

Our proposed heuristic is inspired by previous work by a Kaggle competitor, who proposed a different heuristic algorithm, based on minimizing the variance between row counts in each fold \citep{Wasikowski2019}.
We refer to this previous algorithm as the Wasikowski heuristic, which is used in the StratifiedGroupKFold class, available in scikit-learn since version 0.24.2 (TODO cite release notes 2020).
However, close inspection of the Wasikowski heuristic reveals that it is relatively inefficient, $O(K^2 SG)$ time and $O(SG)$ memory for $K$ folds, $G$ groups, and $S$ strata (Table~\ref{tab:complexity}).
The quadratic time complexity can be prohibitive for a large number of folds $K$, and the memory complexity can be prohibitive if both $S$ and $G$ are large.
This paper proposes new heuristic algorithms with reduced asymptotic time and memory complexity (Table~\ref{tab:complexity}).

\section{Algorithms}

Assume we have a data set with $N$ rows in $S$ strata and $G$ groups.
We want to perform $K$-fold cross-validation, such that data in each group are assigned the same fold ID (no data leakage), and the strata proportions in are approximately equal across folds.

\subsection{Pseudo-code for greedy fold assignment}

The previous Wasikowski algorithm, and our proposed algorithms, are all greedy heuristics which we summarize using the pseudo-code:

\begin{verbatim}
def assign_folds(strata, groups, N_folds):
  count_matrix = zeros(N_strata, N_folds)
  folds = {}
  for group in Sort(groups):
    best_fold = get_best_fold(group)
    folds[group] = best_fold
    count_matrix[,best_fold] += count(group)
  return folds
\end{verbatim}

The algorithm inputs $N$-vectors \texttt{strata} and \texttt{groups}, as well as \texttt{N\_folds} (integer).
The greedy algorithm requires storing the current number of strata assigned to each fold in \texttt{count\_matrix}, which starts with zeros.
The \texttt{Sort()} sub-routine is used to determine the order groups will be considered by the greedy algorithm, and then each group is assigned to a fold in the for loop.
For each group, the \texttt{get\_best\_fold()} sub-routine determines the fold assignment, which is stored for output, and used to update \texttt{count\_matrix}.

\subsection{Previous Wasikowski algorithm}

The previous Wasikowski algorithm uses the following choices for the sub-routines in the pseudo-code.
The \texttt{Sort()} sub-routine uses the variance of the strata counts (max variance assigned first), which has some drawbacks that are discussed in section TODO.
The $O(K^2 S)$ time \texttt{get\_best\_fold()} sub-routine loops over possible folds, adding the current group’s strata counts to current fold’s column of \texttt{count\_matrix}, which is then summarized by computing standard deviation (SD) over folds for each stratum, and finally mean of the SD values over strata.
The \texttt{count(group)} sub-routine involves computing a matrix of counts for each stratum and group, which takes $O(SG)$ memory.
This algorithm is implemented in scikit learn, and has overall $O(N\log N+K^2SG)$ time, $O(N+KS+SG)$ memory complexity (Wasikowski algorithm in Table~\ref{tab:complexity})

\subsection{Proposed online counting algorithm for reduced memory complexity}

The previous algorithm’s $O(SG)$ memory complexity can be prohibitive if there are a large number of strata and groups.
We propose to sort all data rows by group, so the for loop over groups becomes a for loop over data rows, and the \texttt{count(group)} sub-routine computes a vector of strata counts for the current group (no need for a matrix of counts for every group and stratum).
This proposed online counting algorithm can be used with the previous heuristic (Wasikowski-L in Table~\ref{tab:complexity}), and with our proposed squared error minimization heuristic (RSS in Table~\ref{tab:complexity}).
Both have no more $O(SG)$ term in memory complexity (Table~\ref{tab:complexity}), so can be used with a large number of strata and groups.
\subsection{Proposed squared error minimization for reduced time complexity}

For each row $i\in\{1,\dots,N\}$, we have a stratum $s_i\in\{1,\dots,S\}$, and a group $g_i\in\{1,\dots,G\}$.
The algorithm begins by counting the number of data in each stratum, then dividing by the number of folds, to obtain the ideal number of rows which could appear in each fold.
For each stratum $\sigma\in\{1,\dots,S\}$, the ideal number of rows is
\begin{equation}
n^*_\sigma = \sum_{i\in\{1,\dots,N\}}
I[s_i = \sigma]/K,
\end{equation}
where $I[\cdot]$ is the indicator function (1 if argument is true, 0 otherwise).
Table~\ref{tab:counts} (ideal row) shows $n^*_\sigma$ values for $K=4$ fold cross-validation in four real data sets.

For each stratum $\sigma$ and fold $\phi\in\{1,\dots,K\}$, let $\hat n_{\sigma,\phi}$ be the number of data with that stratum assigned to that fold (\texttt{count\_matrix} in the pseudo-code).
The optimization problem is to find a fold assignment which minimizes the residual sum of squares,
\begin{equation}
\text{RSS}=
\sum_{\sigma\in\{1,\dots,S\}}
\sum_{\phi\in\{1,\dots,K\}}
(\hat n_{\sigma,\phi} - n^*_\sigma)^2.
\end{equation}

The algorithm starts with all $\hat n_{\sigma,\phi}=0$ and then assigns a fold to one group at a time.
Let $c_1,\dots,c_S $ be the counts of data in each stratum for the current group, \texttt{count(group)} in the pseudo-code.
We propose assign the group to the fold that minimizes the RSS after assignment,
\begin{equation}
\min_{k\in\{1,\dots,K\}}
\sum_{\sigma\in\{1,\dots,S\}}
\sum_{\phi\in\{1,\dots,K\}}
\big(
(\hat n_{\sigma,\phi}+c_\sigma I[\phi=k]) - n^*_\sigma\big)^2.
\label{eq:RSS} 
\end{equation}
Expanding the square and simplifying yields
\begin{eqnarray}
  \min_{k\in\{1,\dots,K\}}
  &&
     \sum_{\sigma\in\{1,\dots,S\}}
     \sum_{\phi\in\{1,\dots,K\}}
     \hat n^2_{\sigma,\phi}
     - 2 \hat n_{\sigma,\phi} n^*_\sigma+ {n^*_\sigma}^2
     \nonumber\\
  &&
+ I[\phi=k] c_\sigma ( 2 \hat n_{\sigma,\phi} + c_\sigma - 2n^*_\sigma ).
\end{eqnarray}
The first three terms above are the current RSS~(\ref{eq:RSS}), which does not depend on $k$, so it is a constant that we can remove from the min.
Furthermore, the indicator function cancels the sum over folds $\phi$:
\begin{equation}
\text{RSS} + \min_{k\in\{1,\dots,K\}}
\sum_{\sigma\in\{1,\dots,S\}}
c_\sigma ( 2 \hat n_{\sigma,k} + c_\sigma - 2n^*_\sigma ),
\end{equation}
% Simplifying yields
% \begin{equation}
% \text{RSS} + \min_{k\in\{1,\dots,K\}}
% \sum_{\sigma\in\{1,\dots,S\}}
% c_\sigma\big(c_\sigma+2(\hat n_{\sigma,k}-n^*_\sigma)\big),
% \end{equation}
which can be solved in $O(KS)$ time.
Taking the argmin, we remove terms that do not depend on $k$:
\begin{equation}
  \label{eq:k*}
k^* = 
\argmin_{k\in\{1,\dots,K\}}
\sum_{\sigma\in\{1,\dots,S\}}
c_\sigma \hat n_{\sigma,k}.
\end{equation}
We propose using~(\ref{eq:k*}) for the \texttt{get\_best\_fold()} sub-routine in the pseudo-code.

\subsection{Proposed sort method and tie-breaking rules}

This equation assigns the fold ID which results in min RSS.
If there is more than one fold with the same RSS value, then we tie-break by minimizing the amount past the ideal.
For example, if ideal is 100, then 99 should be preferred over 101 (even though both have same RSS).

Each group is represented by a vector of counts, one element per stratum.
For example with 3 strata, two count vectors are [ 3, 3, 2 ] and [ 0, 1, 0 ].
Previous sort method uses SD, so [ 3, 3, 2 ] is tied with [ 0, 1, 0 ].
However a common heuristic for bin packing is to pack larger items first.
The proposed sort uses RSS of group count vector: sum of squared differences between actual and ideal counts.
The ideal counts are always large, so [ 3, 3, 2 ] has smaller RSS, and our proposed algorithm therefore inserts it before [ 0, 1, 0 ], as desired.

[ 1, 0 ] has variance 0.5 so is inserted before [ 1, 1 ] and [ 10, 10 ], both variance 0.
But we want to insert [ 10, 10 ] first (pack larger items first).
Our algo achieves this desired insertion order: [ 10, 10 ] then [ 1, 1 ] then [ 1, 0 ].
The proposed algo results in better fold assignments for these simple examples.

\subsection{Complexity analysis}
We assume there are $N$ data, $K$ folds, $G$ groups, and $S$ strata.
All algorithms begin by sorting the groups, typically $O(N\log N)$ time.

The previous Wasikowski algorithm begins by computing a $G\times S$ matrix of counts per group and stratum, requiring $O(GS)$ time and memory.
For large $G$ and $S$, this large count matrix will be very sparse (almost all entries zero), which is inefficient.
Because the large size of this matrix could be prohibitive, we propose to modify the Wasikowski algorithm to avoid this inefficiency.
Our proposed memory-efficient variant is called Wasikowski-L in Table~\ref{tab:complexity} (L for Limited memory).
We propose to first sort the data by group, then compute and store a count vector for only the current group, thus reducing the memory requirement to $O(S)$, which can be ignored since it is smaller than $O(N)$ (Table~\ref{tab:complexity}, proposed rows, Memory column).

The previous Wasikowski algorithm maintains a $K\times S$ matrix of counts per fold and stratum.
The \texttt{get\_best\_fold()} method considers putting the new group in each of the $K$ folds, then computes SD over folds for each stratum, then mean of SD values over strata.
The \texttt{get\_best\_fold()} method is therefore $O(K^2 S)$ time, and the overall algorithm is therefore $O(N\log N + K^2 G S)$ time (Table~\ref{tab:complexity}, Wasikowski rows, Time column).

The proposed RSS minimization procedure~(\ref{eq:k*}) has a sum over $S$ terms inside a min over $K$ terms.
The proposed \texttt{get\_best\_fold()} is therefore $O(SK)$ time.
Comparing to the previous Wasikowski algorthm, the proposed RSS minimization is asymptotically faster (linear rather than quadratic in the number of folds $K$).

\subsection{Tie-breaking}

In this section we show an example where the tie-breaking rules are necessary for optimal fold assignment.
It involves $N=22$ data with $G=6$ groups, $S=2$ strata, and $K=2$ folds.
The groups are [ 1, 1 ],  [ 3, 0 ],  [ 5, 3 ], and three groups with the counts [ 1, 2 ].
The total is [ 12, 10 ], so the ideal is [ 6, 5 ].
For the groups [ 3, 0 ] and [ 1, 2 ], we have RSS=34 and 3 data.
To tie-break, we would like to first insert a group with more data in larger strata (pack larger bins first).
In this case, that is [ 3, 0 ].
We propose to compute freq = mean(ideal*group), which is 9 for [ 3, 0 ] and 8 for [ 1, 2 ].
Using this tie-breaking rule, the greedy heuristic obtains the optimal fold assignment in these data.
In contrast, the previous rule results in a sub-optimal fold assignment.
